# 飞书需求文档解析说明

> 技术方案（架构/接口/实施状态）见同目录：[飞书需求解析技术方案.md](./飞书需求解析技术方案.md)。

## 1. 功能概述

在 **AI 用例生成 → 需求分析**（`/ai-generation/requirement-analysis`）中，支持通过飞书文档链接自动拉取需求正文，并复用现有 AI 流水线生成测试用例。

| 项目 | 说明 |
|------|------|
| 入口 | 需求分析页 → 需求来源「飞书文档」 |
| 鉴权 | **用户 OAuth**（`user_access_token`） |
| 支持链接 | 新版文档 `/docx/{token}`、知识库 `/wiki/{token}` |
| 不支持 | 旧版 Docs `/docs/`、多维表格、用户未授权的文档 |

核心原则：**飞书只负责拉取正文**；生成 / 评审 / 采纳仍走现有 `testcase-generation` 流水线。

```text
连接飞书账号（OAuth 一次）
  → 粘贴 docx/wiki 链接并解析
  → 预览/微调标题与正文
  → 调用 testcase-generation/generate/
  → 流式或完整输出生成用例
```

与「企业应用身份（tenant_access_token）」方案的区别：用户授权后，可读取**该用户本人已有权限**的文档，一般**无需**再对每篇文档执行「添加文档应用」。

## 2. 飞书开放平台准备

### 2.1 创建企业自建应用

1. 登录 [飞书开放平台](https://open.feishu.cn/app)，创建**企业自建应用**。
2. 在「凭证与基础信息」获取 **App ID**、**App Secret**。
3. 在「权限管理」申请并开通（至少）：
   - `offline_access`（用于刷新 `user_access_token`）
   - `docx:document:readonly`（或 `docx:document`）
   - `wiki:wiki:readonly`（或 `wiki:wiki`）
4. 创建版本并**发布**，确保可用范围覆盖需要使用的成员。

### 2.2 配置重定向 URL

在应用「安全设置 → 重定向 URL」中添加与平台配置**完全一致**的回调地址，例如本地：

```text
http://127.0.0.1:8000/api/requirement-analysis/feishu/oauth_callback/
```

生产环境请改为实际后端域名，并同步修改 `config.yaml` / 环境变量中的 `FEISHU_REDIRECT_URI`。

## 3. 平台配置

编辑项目根目录 [`config.yaml`](../config.yaml)（优先级：环境变量 > config.yaml > 默认值）：

```yaml
# ========== 飞书开放平台（企业自建应用 + 用户 OAuth） ==========
FEISHU_APP_ID: "cli_xxxx"
FEISHU_APP_SECRET: "xxxx"
FEISHU_BASE_URL: https://open.feishu.cn
FEISHU_ACCOUNTS_URL: https://accounts.feishu.cn
# 须与飞书开发者后台「安全设置 → 重定向 URL」一致
FEISHU_REDIRECT_URI: http://127.0.0.1:8000/api/requirement-analysis/feishu/oauth_callback/
# OAuth 成功后跳转回前端需求分析页
FEISHU_FRONTEND_REDIRECT: http://localhost:3000/ai-generation/requirement-analysis
FEISHU_OAUTH_SCOPES: "offline_access docx:document:readonly wiki:wiki:readonly"
```

执行数据库迁移（首次或升级后）：

```bash
cd backend
python manage.py migrate requirement_analysis
```

相关表：

| 表名 | 说明 |
|------|------|
| `feishu_user_auth` | 用户绑定的飞书 `access_token` / `refresh_token` |
| `feishu_oauth_state` | OAuth `state`（防 CSRF，落库避免多进程丢失） |
| `testcase_generation_task` | 任务字段 `source_type` / `source_url` 用于溯源 |

运维自检（仅校验应用凭证，非用户授权）：

```http
POST /api/requirement-analysis/feishu/test-connection/
```

## 4. 使用步骤

1. 登录 TestHub，进入 **AI 用例生成 → 需求分析**。
2. 选择需求来源 **飞书文档**。
3. 点击 **连接飞书账号**，在飞书授权页同意权限后自动跳回平台。
4. 粘贴飞书文档或 Wiki 链接，点击 **确定解析**。
5. 确认/微调标题与正文，选择关联项目（可选），点击 **生成测试用例**。
6. 按页面设置的输出模式查看流式/完整结果，并可保存、采纳用例。

断开连接：飞书面板中点击 **断开连接**，将删除本平台保存的飞书令牌。

## 5. 接口说明

前缀：`/api/requirement-analysis/feishu/`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `oauth_status/` | 登录用户 | 是否已连接飞书 |
| GET | `oauth_authorize_url/` | 登录用户 | 返回飞书授权页 URL |
| GET | `oauth_callback/` | 公开（state 校验） | 飞书回调，换 token 后跳转前端 |
| POST | `oauth_disconnect/` | 登录用户 | 解除绑定 |
| POST | `fetch/` | 登录用户 + 已 OAuth | Body: `{ "url": "..." }` → `{ title, content, source_url, document_id, doc_type }` |
| POST | `test-connection/` | 登录用户 | 校验 `FEISHU_APP_ID/SECRET`（tenant） |

生成用例仍使用：

```http
POST /api/requirement-analysis/testcase-generation/generate/
```

可附带：

```json
{
  "title": "需求标题",
  "requirement_text": "正文...",
  "project": 1,
  "output_mode": "stream",
  "source_type": "feishu",
  "source_url": "https://xxx.feishu.cn/docx/xxxx"
}
```

## 6. 权限与错误说明

| 场景 | 错误码（参考） | 处理建议 |
|------|----------------|----------|
| 未配置 App 凭证 / 回调地址 | `not_configured` | 检查 `config.yaml` |
| 未连接飞书 | `need_oauth` | 点击「连接飞书账号」 |
| 授权过期 / refresh 失败 | `need_reauth` | 重新连接飞书 |
| 当前用户无文档阅读权 | `permission_denied` | 请文档所有者分享给该飞书用户 |
| Wiki 非 docx 节点 | `unsupported_wiki_type` | 仅支持挂载为新版文档的 Wiki |
| 链接格式错误 | `invalid_url` / `unsupported_url` | 使用 `/docx/` 或 `/wiki/` 链接 |
| 正文过长（默认上限 10 万字符） | `content_too_long` | 拆分文档后重试 |

说明：

- **API 权限**（开发者后台开通）≠ **文档资源权限**（用户本人是否可读该文档）。
- 用户 OAuth 下，可读范围 = 该飞书用户在飞书侧已有的阅读权限。
- 若需求集中在某个知识库，也可在飞书侧将应用/群加入知识空间成员，作为补充手段；日常粘贴任意链接场景以用户 OAuth 为主。

## 7. 实现要点（开发参考）

| 模块 | 路径 |
|------|------|
| 客户端 | `backend/apps/requirement_analysis/feishu_client.py` |
| API | `backend/apps/requirement_analysis/views.py` → `FeishuViewSet` |
| 模型 | `FeishuUserAuth`、`FeishuOAuthState`、`TestCaseGenerationTask.source_*` |
| 前端 | `frontend/src/views/requirement-analysis/RequirementAnalysisView.vue` |
| API 封装 | `frontend/src/api/requirement-analysis.js` |
| 文案 | `frontend/src/locales/lang/zh-cn/requirement.js`、`en/requirement.js` |

OAuth 流程摘要：

1. 前端请求 `oauth_authorize_url/`，后端生成 `state` 写入 `feishu_oauth_state`，返回授权 URL。
2. 用户在飞书同意后，浏览器跳转 `oauth_callback/?code=&state=`。
3. 后端校验 `state`，调用 `authen/v2/oauth/token` 换取令牌并写入 `feishu_user_auth`，再跳转 `FEISHU_FRONTEND_REDIRECT?feishu_oauth=success`。
4. `fetch/` 使用当前用户的 `user_access_token`（临近过期则自动 refresh）调用 wiki/docx 接口取正文。

## 8. 常见问题

**Q: 还需要每篇文档「添加文档应用」吗？**  
A: 用户 OAuth 方案下，通常不需要。只要文档已分享给该飞书用户即可。若仍 403，优先检查文档分享权限与应用 scope 是否齐全。

**Q: 授权后立刻解析失败？**  
A: 确认回调 URL 与后台配置一致、应用已发布、`offline_access` 已开通且出现在 `FEISHU_OAUTH_SCOPES` 中。

**Q: 多人共用一个 TestHub 账号？**  
A: 飞书令牌按 TestHub 用户绑定。换人使用请断开后重新连接自己的飞书账号，避免读到他人权限范围外的文档或权限错乱。

**Q: 国际版 Lark？**  
A: 可将 `FEISHU_BASE_URL` / `FEISHU_ACCOUNTS_URL` 调整为对应 Lark 域名，并保证链接域名解析逻辑已覆盖（代码支持 `larksuite.com`）。
